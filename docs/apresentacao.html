O problema

A proposta

Um cockpit que responde na hora — e mostra por quê.

Não é um chatbot genérico sobre os dados. É um assistente que só afirma o que consegue provar: toda resposta numérica vem de uma consulta real aos indicadores, nunca de um palpite do modelo de linguagem.

  • Linguagem natural, em português — a diretoria pergunta como já pensa, sem dashboards para decifrar.
  • Explicabilidade por padrão — "explique o motivo" e "quais indicadores sustentam" são perguntas de primeira classe, não um extra.
  • Simulação, não só consulta — "e se atrasar 30 dias?" vira um número calculado, reproduzível, não uma estimativa da IA.
  • Resiliente — dois provedores de IA em cascata; se um cai, o outro assume, sem o usuário perceber.

Uso de IA

Tool use em vez de prompt cru — e um plano B por padrão.

  • A LLM só decide, nunca calcula. Toda afirmação numérica vem de uma função determinística — risco, orçamento, simulação de atraso.
  • Explicação rastreável. "Explique o motivo" reaproveita os mesmos dados já consultados na conversa.
  • Plano de ação com lastro. É a única resposta em texto livre — e mesmo assim, ancorada nos indicadores já retornados.

Plano de implementação

Do zero ao protótipo funcional em quatro fases.

FASE 1

Fundação

Dados mockados, cálculo de risco e simulação — funções puras, testáveis isoladamente.

FASE 2

IA & Tools

Integração com Claude via tool use, cada ferramenta ligada a um dado real do sistema.

FASE 3

UI & Resiliência

Chat com contexto de conversa, painel de risco, fallback de provedor, tratamento de erro.

FASE 4

Polish & Ensaio

Revisão de segurança, cronometragem das perguntas-âncora, ajustes finais de UI.

Implantação em produção

O caminho do MVP até rodar com dados reais.

  • Hospedagem: Next.js full-stack, deploy contínuo (ex.: Vercel), sem servidor dedicado.
  • Segredos: chaves de API só em variáveis de ambiente do servidor, nunca no cliente — já é a regra do MVP.
  • Dados reais: primeiro 1–2 fontes (ex.: ERP + Planejamento), validar, então expandir.
  • Governança: autenticação corporativa, permissão por empreendimento/região, trilha de auditoria de quem perguntou o quê.
  • Observabilidade: log de perguntas sem resposta, latência por provedor, taxa de fallback acionado.
